■ターン処理
1. 両者のコマンド選択が完了する
　→コマンドはAPIでサーバに渡される
2. 交換判定
  2.1. 両者が交換の場合
    2.1.1. 
  2.2. 片方が交換の場合
    2.2.1. need-switchをturnAction配列に詰めてクライアントに送信
      →交換するプレイヤーは交換ポケモンを選択して交換用API実行、交換しないプレイヤーは待機
    2.2.2. turnAction配列の要素をクリアする
    2.2.3. 交換用APIが送信されてきたらswitchをturnAction配列に詰める
    2.2.4. 3. へ
3. イニシアティブ判定（先攻／後攻判定）
  3.1. 両者がmoveの場合
    3.1.1. 両ポケモンの素早さを比較し、数値が高い方を先攻とする
    3.1.2. 4. へ
  3.2. 片方だけmoveの場合
    3.2.1. moveのポケモンを先攻とする
    3.2.2. 4. へ
4. 先攻攻撃
  4.1. 先攻ポケモンの与ダメージを計算する（命中判定も実施する）
  4.2. 後攻ポケモンのHPを計算する
  4.3. 瀕死判定
    4.3.1. HP > 0 の場合
      4.3.1.1. 5. へ
    4.3.2. HP = 0 の場合
      4.3.2.1. need-switchをturnAction配列に詰めてクライアントに送信
        →交換するプレイヤーは交換ポケモンを選択して交換用API実行、交換しないプレイヤーは待機
      4.3.2.2. turnAction配列の要素をクリアする
      4.3.2.3. 交換用APIが送信されてきたらswitchをturnAction配列に詰める
      4.3.2.4. 5. へ
5. 後攻攻撃
  5.1. 後攻ポケモンの与ダメージを計算する（命中判定も実施する）
  5.2. 先攻ポケモンのHPを計算する
  5.3. 瀕死判定
    5.3.1. HP > 0 の場合
      5.3.1.1. 6. へ
    5.3.2. HP = 0 の場合
      5.3.2.1. need-switchをturnAction配列に詰めてクライアントに送信
        →交換するプレイヤーは交換ポケモンを選択して交換用API実行、交換しないプレイヤーは待機
      5.3.2.2. turnAction配列の要素をクリアする
      5.3.2.3. 交換用APIが送信されてきたらswitchをturnAction配列に詰める
      5.3.2.4. 6. へ
6. ターン終了処理
  6.1. プレイヤーコマンド等の変数の値をクリアする
  6.2. 1. へ
